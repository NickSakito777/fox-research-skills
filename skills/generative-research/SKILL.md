# 研究框架生成与迭代

按本轮任务选择或组合四项能力：系统搜索相关资源，拆解机制与实现链，组织用户的理解过程，形成可追溯的研究判断与下一步。不要求每次全部执行。双循环、问题记录和行动选择为这些能力提供支持，按需使用。

需要追问驱动的地图更新、证据片段核验、逐步共读、条件决策或中断恢复时，读取 [可复用研究方法](references/external-methods.md) 的对应段落。方法已写在本仓库；来源链接用于溯源，不是运行依赖，也不代表已经安装相应外部系统。

## 接续目标与范围

从当前请求、已确认选择和材料明确目的、边界、已有证据、交付与投入限制；需要帮助用户理解时，明确本轮希望能解释或区分什么。研究约定可以是一段话，不固定增加问卷或表格。

区分用户明确目标、已确认约束、待检验前提与 agent 的意图假设。可以提出更合适的问题表述或纠正事实前提；改变主要目标、显著扩大投入，或出现尚未明确的价值取舍时再与用户对齐。已有授权和偏好继续沿用。

用户只要求讨论框架时，完成该阶段，不展开正式调研或制作页面。窄问题、单篇共读和已有研究的接续保持相应范围；接续时先核对已有判断与未决问题。

## 问题重述与跨领域方法迁移

用户希望跳出既有框架、寻找其他领域的成熟方法，或借外部知识发现未知缺陷时，读取 [问题重述与方法迁移](references/cross-domain-transfer.md)。支持从已有疑点向外找，也支持外部发现先改变问题；不要求先锁定缺陷、性能指标或唯一基础学科。

先看现有方案的机制、约束与选择，再尝试其他表述和结构对应。检索与深读要能回到“这个外部方法改变了哪条假设、揭示什么问题、可借哪一部分”；问题实质改变后更新检索。用户只需共同思考时，由 [Pair Writing](../pair-writing/SKILL.md) 选择一处有用的视角推进，不自动展开整套迁移审查。

## 系统搜索与领域覆盖

围绕问题生成暂定框架：研究边界、比较单位及其关系、重要维度、取证入口和覆盖判断。用少量异质材料或已有资料检验；保留稳定对象身份，允许多视角和交叉分类。领域字段随题目生成，通用示例按需见 [案例与行为检查](references/cases.md)。

从用户种子扩展术语、代表对象及前后向引用，同时采用互补的独立发现入口。根据主张选择论文、代码、产品、标准、专利或其他资源；来源类型用于组织取证，不直接充当对象分类。关联同一对象的多类材料，保留来源、版本和引用依赖。

论文发现与范围筛选不按全文是否免费、开放获取或可下载来排除。围绕题目覆盖相关期刊、会议及其他适用文献，访问状态另记；相关论文因付费墙或获取失败暂时无法深读时，保留身份、现有信息和待核事项。除用户明确限定外，不将仅开放获取或 PDF 可得过滤设为默认。广泛检索不等于已穷尽全部文献。

需要可复核的检索、筛选、全文获取或研究质量评价时，读取 [可复用研究方法](references/external-methods.md) 的对应段落；固定主要检索策略前，用已有相关报告预检召回并处理漏检。没有已知报告时先从初步发现建立预检集，不把初步发现本身记为预检完成。发现、获取、质量和核验状态分开，避免可读资料决定研究边界。

探索初期，发现新的概念、对象、路线和关系，建立可导航的领域地图，本身就是有效进展。不要求每次搜索立即改变已有判断；尚无足够判断依据时，先形成对象与问题的轮廓。

按与目标有关的机制、任务、形态、实现或其他维度检查覆盖。给已发现对象、用户种子和外围分支留下纳入、归并、暂缓、排除或待核去向及理由。记录重要检索路径、访问限制和覆盖缺口；条目数、查询数和来源数不单独证明全面。外围发现不自动扩成本轮必做任务。

## 机制、技术链与实现依赖

技术深读围绕重要环节及其连接展开。说明各环节的输入、输出及含义，输出怎样满足下一环节的输入要求，依赖哪些前置条件；解释关键实现选择及取舍、如何验证该环节和连接、在哪些条件下会失效。

把论文主张、公开实现和实际运行证据对应起来。根据任务追到公式、算法、数据处理、接口、代码或装置的具体位置；材料未说明的接口和依赖保留为缺口。多个环节分别有效，不能直接证明整条链已经可用。

需要判断某个组件或做法是否必需时，进行去除或替换分析，区分所需功能、可替换实现与任务优化。解释系统失效时，沿原始观察、加工后的表示与推断结果定位分歧；同一批材料在哪一步失去区分能力，决定先查采集、处理还是学习。诊断与竞争解释的具体用法见 [问题重述与方法迁移](references/cross-domain-transfer.md)，不把一种表示或模型的失败写成任务本身无解。

## 组织用户的理解

以本轮认知目标安排全景定位、同口径比较与逐层解释：先说明对象或环节处于什么位置，再解释关键差异为何影响理解或选择，最后提供原文、公式、实现、条件和争议的追溯入口。

选择能回答具体问题的地图、技术链、对照表、时间线或关系图，不为齐全而制作所有视图。重要框架变化应解释原先怎么看、新材料揭示了什么、现在为何调整。用户参与点围绕值得判断的分歧，避免反复询问是否继续已授权工作。

多对象资料、可视化、问题追踪或跨会话接续按需读取 [记录与表达](references/records-and-views.md)。视图与报告共享证据记录；页面制作及分享依本次交付要求进行。环境提供专门的研究地图能力时可按需配合，但它不是本 Skill 的安装依赖。

## 形成判断、未决问题与下一步

把关键主张与原始位置、版本、任务条件及指标口径连接起来。先解释可比性，再综合或推荐；资料可访问、代码公开与实际运行分别记录。保留相反证据、冲突条件和具体缺口，区分未查、访问受阻、未报告与不适用。搜索没找到只支持检索缺口。

形成在当前证据和条件下成立的判断，说明未解决的问题与可能改变判断的发现。探索任务可以以有边界的领域理解和问题地图交付；决策任务再结合已确认的目标权重收敛候选。

允许证据驱动假设和探索性设想，分别说明依据或动机、所依赖的假设、适用条件，以及有判别力的初步验证方式。检验失败应说明否定了哪条假设或哪种实现；跨领域类比用于生成假设，不能单独作为结论证据。主张类型、核验状态和问题状态分别记录，具体方式见 [记录与表达](references/records-and-views.md)。

## 按需选择行动与调整框架

在进入新一轮研究、准备转向或收尾时，判断当前需要发现新方向，还是处理事实缺口、证据冲突、不可比条件、机制不清或框架局限。不要求每次工具调用都执行一套检查。

- **框架内求证**：沿当前问题和比较方式扩展证据、区分解释或解决关键缺口。
- **框架外探查**：检查问题表述、对象粒度、比较轴、边界或默认前提，寻找会改变研究重点的观察方式。

框架外探查的时机包括：来源高度同质或沿用同一假设，重要对象反复难以归类，指标与目标脱节，出现影响关键判断的反例，或准备判断覆盖充分但尚无独立于现有分类的发现路径。限定探查问题、投入和返回条件；已有检查仍适用时复用，不固定生成多套框架。

选择行动时，定性比较其对目标的影响、发现价值或区分解释的能力、材料可获得性与成本。探索初期可以优先扩大可见范围；证据逐渐充足后加强核验和收敛。重要但当前不可回答的问题注明缺少的条件，继续推进其他有价值的工作。

所选行动可以是检索、原文深读、计算、来源核验、框架比较、实验设计或用户澄清。明确希望了解什么、哪些结果构成有效发现或支持反驳，以及结果如何影响判断、框架、优先级或停止条件。不要用持续检索替代所缺的数据或实验；未明确的目标或价值权重由用户选择。

框架重构需改善重要解释、消除关键混淆、暴露系统性遗漏、改变优先级，或使问题更容易检验。特殊对象可先按例外、多标签或外围分支保留。重要调整简记“原框架 → 触发材料 → 新框架 → 受影响的记录与判断”；避免仅为新名称反复重排。

## 组织执行

广度、多来源调研默认使用多个 agents，前提是当前环境允许协作且任务能拆出独立工作。调用本 Skill 开始此类研究即按该策略执行，不重复询问是否多 agent；这项分工不扩大用户对外部写入、发布或高风险操作的授权。仅讨论、窄问题和单篇共读可以由主 agent 完成。

主 agent 保留有用的本地工作，负责合并与判断。分工服务于当前发现或取证需要，模型、规模和预算遵从用户选择与实际能力；按新发现调整后续任务。正式分工前读 [执行与合并](references/execution.md)，区分独立发现、挑战、核验与综合的任务要求。协作能力不可用时顺序执行，并准确报告。

## 交付、接续与方法反馈

按约定交付本轮选用能力的结果与必要证据，明确关键发现、判断、未决问题和下一步理由。需要继续加工或跨会话推进时，维护最小接续状态；需要复用时提供结构化资料与可打开的入口。只报告实际完成的搜索、核验、运行与页面检查。

结束时区分：本轮目标已得到足够回答、限定检索范围趋于饱和、资源到限，或继续推进需要新的数据、实验或外部条件。检索饱和不自动证明框架充分；发现与判断的成熟程度按实际交付说明。

事实修正进入用户指定的知识或记录流程，方法反馈依据可观察行为记录。只有当前任务授权覆盖更新时才修改 Skill 或其他持久文件。
