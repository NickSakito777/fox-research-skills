# 案例与行为检查

这些案例只展示如何按题目生成字段和检查行为，不是固定领域模板，也不要求每次读取。

## 城市树木降温

一个看似简单的问题——“树能让街道降温多少”——可能混合不同机制与测量对象：

- 遮阴主要改变短波辐射与表面温度，蒸腾主要影响能量与水分交换。
- 气温、地表温度和人体热舒适不是同一输出，不能直接合并成一个“降温幅度”。
- 树种、冠层、土壤水分、街谷几何、风、时间尺度和测点位置会改变观察结果。
- 现场传感、遥感与模型输出的空间和时间口径不同，比较前应先对齐单位与条件。

可迁移经验：先拆机制、观测和目标，再生成比较字段；来源报告的数字必须和测量条件一起保留。新证据若表明原问题混合了多个输出，应先重述问题再继续检索。

## 开源技术路线比较

比较开源研究工具时，可以把论文、代码仓库、托管服务、数据集和实际运行记录保留为不同对象，再沿技术链检查：

- 公开描述声称解决什么问题，核心功能是否出现在真实调用路径中。
- 输入、输出、依赖、数据与配置是否齐全，仓库版本是否对应论文版本。
- 有代码、能安装、能运行和对目标任务有效分别达到哪一层。
- Stars、更新时间和 issue 数量只能辅助发现，不能替代源码、测试和运行证据。

可迁移经验：关联同一对象的多类资料，但不把多份页面当作多次独立验证；比较实现成本时同时检查许可、依赖和维护证据。

## 按行为检查迁移

检验输出行为，不通过匹配标题、固定字段或固定措辞评分：

| 场景 | 应观察的行为 |
|---|---|
| 陌生领域、种子很少 | 建立术语、对象、路线与关系；将有效发现作为进展，不强求每次立即改判 |
| 技术深读、实现材料不完整 | 解释输入输出和环节连接，指出前置条件、实现选择、验证方式与失效边界；不把局部性能当作整链已验证 |
| 多份材料共用原始实验或默认前提 | 追溯共同出处，并按需要寻找不依赖同一种子的发现入口 |
| 指标不同、证据冲突或框架遗漏 | 区分问题性质，选择适合的行动，不直接排名或投票 |
| 特殊对象与系统性反例并存 | 区分例外记录和有价值的框架重构，说明受影响的判断 |
| 重要问题当前不可回答 | 标明阻碍或暂缓原因，选择其他有发现价值或判别力的可行行动 |
| 用户只要讨论，或证据之外仍有价值取舍 | 遵守阶段范围，复用已知选择，将尚未明确的目标交还用户 |
| 换领域或跨会话接续 | 重新选择适用维度，恢复已有判断与未决问题，按变化增量推进 |

修改 Skill 前先说明希望改变的可观察行为。结构检查和隔离小样本只支持其实际检查范围，不能替代真实任务迁移或长期使用证据。
