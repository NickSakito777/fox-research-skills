# 问题重述与方法迁移

用于跳出已有表述、借外部知识发现问题，或寻找可拆用的理论、算法、建模和训练方法。按当前缺口选择动作，允许往返；这不是每轮必填的表格或固定阶段。Pair Writing 的轻量讨论在其正文中执行，系统搜索、深读和迁移审查再读取本文件。

## 保留两种探索入口

- **已有疑点向外找**：某个选择、现象或约束值得重新解释，去其他领域寻找原理与方法。
- **外部发现向内看**：先看到一种此前不知道的能力或解释，再回头检查原方案有哪些假设、缺陷或被忽略的机会。

探索既可改变解法，也可改变问题定义、观察单位和证据要求。不要预设外部领域一定更先进，现有方案一定有缺陷，或每个工程问题都有唯一“原籍”。基础学科、邻近工程、数学与交叉领域均可提供线索；是否相关由具体关系决定。

先保留用户原话及当前想推进的层次：扩展理解、形成问题、找方法或验证候选。概念中的“通用”“泛化”“更好”若仍有实质歧义，提供可选解释；已有澄清优先，不反复索要定义。算法适用范围、跨学科迁移与特定测试条件下的泛化表现分别讨论。

## 从现有方案提取可改变之处

从材料里还原与本题有关的链条：观察什么，经过什么变换，推断什么，最终服务什么目的。沿关键连接区分：

| 项目 | 判断依据 |
|---|---|
| 必要原理或条件 | 原文、推导或观察说明为什么缺少它会使论证失效 |
| 已确认的实际约束 | 当前装置、数据、资源或任务确实限制了选择 |
| 实现选择或惯例 | 作者选了它，但尚未证明只有这一种实现 |
| 未知前提 | 材料未说明，不能立即归为缺陷或可自由取消的约束 |

需要时问“去掉／替换这一步会失去什么”，帮助区分功能和实现。单篇论文的取舍未必是整个领域的缺陷；资料未报告、当前未查到与已有反证分开。

讨论系统误差或某项改进时，沿与本题有关的链条找分叉：原始观察是否含有所需差异，经过变换后是否仍保留，推断或决策是否用到了它。优先用同一批材料对照相邻环节；肉眼判断、简单探针或某个模型分不开，只说明当前检查没有分开，还要看噪声、表示、数据覆盖及方法能力。只有相应条件下的证明或充分证据才支持不可辨识性或性能上限判断。

标签、参考真值和评价协议也会制造表面误差。它们会改变归因时，检查真值是否独立可靠、数据划分及动作／采样规则是否提供了捷径，不自动把全部误差归给被测方法。外部知识还可以改变目标、观察单位、训练信号或数据生成方式；分层诊断只是一个入口，不限定探索必须走向测量修补。

## 用不同表述打开检索入口

保留领域原描述，同时尝试与本题有关的另一种表述，例如从分类转为状态估计，从输出误差转为可观测性，从网络选择转为逆问题，从单个组件转为系统耦合。每个重述说明改变了哪个对象、关系、尺度、目标或假设，以及预期能看到什么遗漏。它们是待检验视角，不自动替代用户目标。

可以暂时去掉专有名词，保留“对象起什么作用、受什么限制、哪些量之间有关系”；回译时必须恢复具体条件。不要为了抽象而抹掉量纲、几何、尺度、时间、噪声、可控性或标签条件中决定适用性的部分。类比越遥远不自动越有价值。

发现资料时并行考虑原领域术语、机制／数学术语、结构相似领域的术语与引用链。综述、经典方法、通用理论、负结果和实现经验都有价值，不照搬只偏好近期实证新方法的过滤器。重要检索沿用 [已知报告预检](external-methods.md)；没有合适已知材料时先建立种子，不编造召回验收。

## 深读一个外部方法，再判断怎样借

先看来源真正解决什么问题，输入输出、有效机制和成立条件是什么；必要时追到公式、方法段、代码与数据接口。再解释它对当前问题的启发，允许结论为不适用。摘要相似、模型联想或知识图路径仅能生成候选。

值得继续的连接，留下足以审查的“迁移说明”；可以是一段话或短表，不要求机械填齐所有字段：

- **当前疑点与来源定位**：被挑战的具体陈述；原文、版本、方法或代码位置。
- **对应关系**：源问题和当前问题中的对象、作用、关系或运算怎样对应；哪些关键部分不对应。
- **成立与失配条件**：按题目检查决定迁移的观测、几何、尺度、信噪比、可得数据、先验或计算条件，缺证据之处留待核。
- **可借部分与改造**：借解释框架、一个估计步骤、先验、训练目标、数据方案或完整方法；说明接口和依赖，不把多个可用零件直接拼成可用系统。
- **带回来的改变**：发现了什么盲点，取消或增加了哪个假设，怎样重述问题；下一次阅读、推导、比较或观察能区分什么。

例如，森林冠层的能量平衡模型可为城市树木降温提供检索连接，但不足以直接迁移到街谷。需要比较几何、风、土壤水分、辐射边界和观测尺度，再判断可借完整模型、部分变量，还是只有一个解释视角。这是迁移检查示例，不是模型已经适用于城市街道的结论。

## 组合、挑战与回查

先保留各来源能独立支持什么，再组合。每条启发保留来源身份和条件；组合的新结论另列为假设，不能借多条引用掩盖中间推理。所谓互补应说明一方弥补了哪一具体缺口，或为什么二者能共享输入输出。

挑战要指向会改变路线的原陈述：当前依据也能由什么竞争解释产生，哪项对照能让两种解释给出不同预测？按需要固定同时变化的条件，比较已有做法或更简单基线；阴性结果要说明否定的是哪条假设、某个实现还是尚无足够信息，不能一次失败就排除整个方向。证据充分时不强造反方。审查者角色、LLM 自评分、投票、相似度阈值不代替证据；“值得探索”“原理适用”“实现可行”“效果更好”“具有新颖性”需要各自的支持。

对照改变了样本或评价条件时，先对齐比较对象，不能凭分数变化分摊未受控差距的因果份额。学习任务重新划分留出数据时，训练、预处理拟合与调参也要保持隔离；固定模型结构不等于沿用已见过留出数据的参数。质量检查按需复用 [研究质量评价](external-methods.md)。

问题、机制或方案实质改写后，更新术语和最接近工作的检索，不复用旧检索为新问题背书。检查是否只是换了名称、是否已有成熟应用，以及外部方法在当前约束下是否失去优势。检索未找到不证明不存在；找到老方法也不使适配工作失去价值。

如果某个候选失配，区分被否定的是类比、某种实现，还是问题本身；必要时沿新发现返回重述。没有缺陷证据时可以保留“尚待理解的选择”，不为产出创新强造缺陷。

## 按本轮目的收尾

交付可以是更好的问题表述、视角与来源地图、可继续深读的连接，或带条件的迁移候选。需要选下一步时，说明它能消除哪个关键未知、所需材料或代价，以及什么结果会改变路线顺序。成熟到可以判别时再提出最小观察、推导或对照实验；探索开始时不必先固定性能指标或编造阈值。

重要变化沿用主正文的简记：原问题／前提 → 触发材料 → 新理解 → 下一步。明确已查、推断和未决之处，保留合理分支，不强制选冠军、固定轮数或生成完整实验提案。普通 Pair Writing 只呈现最能推进当前思考的部分。

## 选择开源材料时

区分方法借鉴、少量代码抽取与整套部署的成本。先看核心功能是否在真实调用路径中、输入／数据／依赖是否齐全、许可是否明确、是否有测试或实际运行证据，再以 Stars 和更新时间辅助排序。库级新提交要看实际内容，并追到目标模块的最近改动。

读 README 后继续读核心实现、相关 open／closed issues、回复及修复位置；状态为 closed、issue 很少或 Stars 很高均不自动证明完善。记录“公开描述、源码存在、静态链路、实际运行、目标任务有效”各自达到哪层。优先复用已有能力，缺失部分作为二次开发任务说明，不用整套平台替代几个思考操作。
