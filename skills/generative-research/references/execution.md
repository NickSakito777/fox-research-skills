# 执行与合并

正式多路调研时读取。分工落实主正文的研究目标与行动选择，不另建一套推进流程；仅讨论或窄问题不必启动完整分工。

## 按研究需要分工

同时考虑对象、机制、来源入口和任务作用。作用可以是发现新方向、扩展已有证据、挑战前提或框架、核验关键主张，或判断材料能否共同支持某个比较与解释。这些是可组合的任务功能，不是固定的 agent 角色。

主 agent 维护研究约定、主资料和重要问题，承担有用的本地工作。worker 处理可独立推进的任务并保留自己的结果。避免没有目的的重复，允许为高影响主张、冲突解决或独立核验安排交叉检查。

## Worker 任务合同

每项委派带上足够的上下文：

- 服务于哪个目标或问题，为什么现在值得处理；探索初期可以是发现尚未知晓的对象、路线与关系。
- 要发现、扩展、挑战、核验或综合什么，包含和排除哪些对象。
- 哪些发现可能影响主框架、关键判断或后续选择；不预填希望得到的答案，不要求每项发现立即改判。
- 已有种子、必要定义、材料与读取权限，以及深度和投入限制。
- 对象、主张、来源、条件与问题的最低记录方式；交付位置或返回格式、结束条件，以及不得覆盖主资料的文件边界。

独立发现任务可先提供总目标、硬约束和必要定义，让 worker 提出观察维度，再与主框架比较；不能为了减少引导而隐去必要条件。核验任务提供待核验主张、出处与适用范围，并检查相反证据和替代解释。

要求返回实际发现及出处、条件、核验状态、重要查询路径和排除理由。没有信息增量时说明查了什么，空结果不能作为领域不存在的证明。

任务有查询、深读或其他投入上限时，批量调用前核对已用与本批额度；记录实际用量和访问深度，意外超额如实保留，不能仍按等额执行汇报。

摘要压缩到足以合并的结果，同时保留原文定位和未完成分支；工具失败、访问受阻或工作中断不能被摘要为“没有相关研究”。局部来源编号合入主记录时建立映射，不沿用含义冲突的编号。

## 合并与后续任务

1. 归一对象身份，处理别名、预印本与正式版、同名仓库及专利族；有关系的研究、产品和工具仍可保留不同类型与身份。
2. 合并字段与主张。指标、条件或版本不同就并列说明，不取平均或凭多数投票消除差异。
3. 回到决定判断的原始证据，将评语逐条对回对象 ID、原句及上下文，防止串用另一对象的论据或替含糊表述补主语。worker 摘要和多个 agents 的一致判断不能替代核验；多份材料引用同一实验时保留共同出处。更正保留原判断、原因及影响，不把事后改分或新标准写成原先结果。
4. 检查对象 ID、关系端点、来源定位、重复项及缺失字段；追踪问题时同步其依据和状态。大规模记录可用脚本，小量直接核对。
5. 将重要新增分支、反例、框架局限及实现连接缺口带回主流程，依据主正文决定继续、改向、询问用户或结束。

主 agent 根据结果调整分工。已有任务可以缩小、改向或结束；新增 worker 对应新的信息需求，不因并发位置空闲而派工。已有授权继续沿用。

## 实际执行记录

按任务规模简记谁做了什么、从哪些入口取证、结果怎样进入综合，以及未完成或受阻部分。向用户报告有助于理解的新发现、判断变化和剩余问题。

协作工具不可用或资源受限时，采用实际可行的执行方式并说明影响；不把顺序执行声称为并行，也不把自查声称为独立核验。
