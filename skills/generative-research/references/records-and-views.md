# 记录与表达

用于多对象资料、技术链解释、交互视图、重要问题追踪或跨会话接续。按本轮需要选择记录，不规定数据库、前端或固定文件数量；小任务可直接用带出处的 Markdown。

## 共享记录

| 记录 | 最低有用内容 |
|---|---|
| 对象 | 稳定 ID、名称／别名、类型、版本、相关性理由及本题比较字段 |
| 来源 | 来源 ID、位置、作者／发布者、日期／版本、访问状态与共同出处 |
| 证据片段 | 来源 ID、原文短引或准确位置、上下文条件；另写它对当前问题意味着什么 |
| 主张 | 关联对象或问题、陈述／值、单位／指标、条件、来源定位、主张类型与核验状态 |
| 关系 | 两端 ID、含义、适用范围和依据；技术连接注明接口与依赖，引用不自动意味着方法继承 |
| 问题 | 与目标的关系、当前判断与依据、状态、改判条件及下一步，见下节 |
| 检索与缺口 | 重要查询入口、实际结果、纳入／排除理由、访问限制与待查去向 |

字段随主题生成。数字随任务、口径和条件一起记录；即使量纲相同，也要分清指标实际测量的属性，不能用数值相近代替概念或性能等价。论文、开源资源与商业状态不排成单一成熟度阶梯。对象在不同视角中保持身份一致。

已有来源 ID 保持稳定；合并别名或版本时保留映射。URL 去重用于避免重复获取，同一论文、实验或数据的多个页面仍需追溯共同出处。提取时允许留下“材料引出了什么新问题”，不把所有发现塞进既定字段。

论文清单将相关性／筛选去向、全文获取状态、研究质量评价和主张核验范围分别记录。全文状态可为未尝试、已取得、摘要可得但全文未取得、需要授权或付费、获取失败、未知；保存已知出处及尝试结果。相关论文未取回不能从候选记录或覆盖缺口中消失，也不等于不适用或低质量。

资料需要继续加工时可用 JSON／CSV 配合可读 Markdown；简单来源关系不必拆成多张表。明确当前真源，让报告、视图和导出文件共用记录，避免各自维护过时副本。

## 主张类型与核验状态

分别记录主张属于事实性陈述、推断或假设、探索性设想，以及实际检查过什么、获得什么支持、存在什么冲突与未覆盖条件。

核对原文可以确认“来源报告了这一结果”，不能自动确认结果适用于当前场景。推断也可经过审查，应保留推导依据。访问到代码、阅读代码和实际运行的核验范围分别说明。

引用核验按需要检查四层：文献身份与版本、原文位置、片段是否支持所述主张、条件是否适用于本题。关键引用固定到实际读到的论文版本、仓库提交或本地快照，再核对题名、章节、表图或页码；未固定的在线链接可能已指向新版，不能把旧摘要、题名或定位与新正文拼成一次核读。版本有变时，只重核受影响的主张；改题名本身不说明原结论被推翻。

区分取得全文、实际深读、只读摘要和访问失败；摘要级支持不能记成全文核验。没有确认位置时保留待核，不以数值一致代替位置核验。DOI 或目录匹配只检查身份与元数据；摘要相关度、模型评分和引用数量不代表主张可靠。

对重要主张区分支持、反对、证据不足及条件不一致，说明理由。条件不一致的结果先并列比较；未报告或未检索到不是反证。关键结论必须能从问题相关摘要回到原文片段与上下文；无法保留引文时记录准确位置和访问限制，不补造片段。

探索性设想记录其相关性或动机、依赖的假设，以及有判别力的初步检查；说明检查失败具体否定哪条假设或哪种实现。跨领域迁移补充来源领域解决的结构性问题、当前相似结构与关键条件差异，不能用类比本身证明可行。

## 问题与接续状态

追踪影响理解或行动的重要问题。跨会话或多人协作时使用稳定问题 ID，关联对象、主张、来源及框架版本；即时窄问题不必单独编号建档。下列信息可以合并在短段落中，不要求逐项建立表格。

| 内容 | 需要保留的信息 |
|---|---|
| 问题与目的 | 正在问什么，为什么影响当前目标 |
| 当前判断 | 已有回答、适用条件及仍未确定的部分；尚无回答时如实保留 |
| 依据与分歧 | 支持、反对或尚不能区分解释的证据及来源 |
| 问题性质 | 涉及事实、机制、比较、框架或决策的哪些方面，可交叉 |
| 状态 | 待解决、暂有回答、受阻、暂缓或排除 |
| 改判条件 | 什么发现会改变判断，或使暂有回答重新开放 |
| 下一步 | 值得采取的发现或求证行动、理由及投入条件 |
| 重启条件 | 暂缓、受阻或排除的原因，以及何时重新检查 |

“受阻”表示缺少必要材料、能力或外部条件；“暂缓”表示当前优先级或投入不合适；“排除”表示不在本轮范围或已有明确排除依据。三者均不自动表示问题没有价值。

长期任务在已有研究记录中维护最小接续状态：当前约定、框架及重要变更、关键判断与证据、未决问题、暂缓或排除路径，以及下一步理由。已有位置能够承载时不另建重复文件。

接续先核对目标和条件，再推进未完问题；增量更新先查新材料影响哪些主张、问题和判断。以能否恢复判断依据并继续工作检验接续效果，文件存在本身不足以证明有效。

中断恢复时将记录的完成状态与实际产物、来源定位和未完成分支对照；已完成且条件未变的部分复用，只重开缺失、冲突或受新材料影响的部分。用户追问先与已有问题归并，再注明本轮新增证据、改变的判断和仍未回答之处。状态摘要不能替代证据，也不能授权覆盖已有文件。

## 按任务附加的记录

- **逐步学习／共读**：可为当前机制记录未涉及、已解释、已检查理解、仍不稳或暂跳过，并注明依据。解释过不等于理解已检查；用户跳过检查时不认定已掌握。这是本轮理解状态，与文献可信度和证据核验状态分开，只有需要接续且允许写入时才保存。
- **路线选择**：区分固定约束、可调参数及待确认权重，记录关键分支、选择依据、失败依赖和改判条件。
- **实验设计**：进入实验决策时记录假设、基线／对照、变量、可观察指标、否定条件及结果会改变什么；未实施的实验保持计划状态。探索地图不强制附实验。

## 阅读层次与视图

每个视图回答具体问题。按需要组织全景定位、关键差异与原因、原始证据和细节的逐层阅读，不强制制作多层页面。

- 机制或能力视角解释对象为何归组，允许多标签。
- 技术链视角展示环节连接与实现依赖；连线说明条件及核验范围，未确认的接口不能画成已验证连接。
- 时间视角区分首次公开、版本更新和产品发布。
- 形态或应用视角解释使用条件与限制。
- 关系视角标明关系类型、来源和假设状态。
- 并排对照使用相同字段，显示不可比条件及缺失。

人工分组不标成算法聚类；节点距离只有在有定义时才表达相似度；资料空缺不能直接命名为创新空间。框架重要变化及影响范围沿用主正文的简记，避免同时维护另一份变更流程。

## 图片与用户问题

优先帮助辨认对象和理解机制的系统总览、装置实物、方法流程及输出示例，给出来源与版本。缺少可靠图片时说明缺图，不用其他产品图片补齐；外部图像遵从实际工具和使用条件。

将用户的问题关联到相应对象或问题记录，并保留其来源和待查事项。草想按其主张类型处理，不直接合入已验证结论。

## 交付检查

按交付形式检查证据和数据一致性、引用、筛选、展开、详情、返回导航、比较、图片及问题导出；实际浏览器检查与静态文件检查分别说明。结构化记录及追加日志保存后重新读取，检查引用关系与中文等非 ASCII 文字能否保持原意；可解析只证明结构有效，不能证明文字保真。出现乱码时回到原记录修正，无法恢复的字段注明缺失，不凭上下文补造。

需要分享时依授权选择离线包或托管。离线包检验换目录后的资源与导航，说明哪些原文链接需要联网；发布或外部推送遵从本次授权。
